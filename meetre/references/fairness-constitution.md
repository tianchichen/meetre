# 公平公约

这份公约是会议判断的公开依据。它不把会议压缩成一个神秘分数，而要求 Agent 展示能被人检查的证据和动作。

## 1. 先说清楚结果

会议结束后必须发生一个可观察的变化：做出决定、解决分歧、共同产出方案、明确责任承诺，或完成需要现场照顾的敏感沟通。“同步一下”“对齐一下”“大家聊聊”本身不是产出。

## 2. 同步要有独占价值

以下情况通常需要实时互动：多方权衡并决策、处理现场分歧、高密度共同创作、紧急事件协调，以及安全、法律、人事或敏感关系沟通。

以下情况优先异步：状态更新、信息广播、例行汇报、没有争议的审批、独立材料评审，以及只需要知道最终结果的知会。

## 3. 角色要与结果相连

合理的同步角色包括决策者、对结果负责的人、不可替代的信息源、需要当场承诺的执行者和直接当事人。学习观察者可以参加，但必须明确是自愿的学习目标。

“让他也知道一下”“以防万一”“一直都邀请”“显得重视”“领导可能想听”不是足够的同步理由。

角色数不等于人数。现实里一个人常常兼几个角色（写方案的人同时是执行负责人，决策者同时是那条信息的唯一来源），所以沙盘允许把一个单人角色并入另一个角色，由同一个人兼任。合并改变的是需要到场的人数和时间成本，不改变角色本身的必要性：被兼任的角色仍然要有人满足它的底线，只不过那个人同时在满足另一个角色。

## 4. 比较总成本

报告中使用以下确定性计算：

```text
同步成本 = 同步人数 × 所有同步议题分钟数
异步成本 = （同步人数 + 异步知会人数）× 所有异步议题阅读分钟数
当前总成本 = 同步成本 + 异步成本
返还时间 = 原始会议成本 - 当前总成本
```

原始会议成本使用会议原始人数乘原始时长。异步不是零成本。
同步参会者也需要阅读被改为异步的议题，因此异步阅读时间由所有未排除人员共同承担。
“无需参与”人数单独展示，不折进时间成本；当前 Result Schema v1 尚未表达每个议题的完整参会名单，不能把 `requiredRoleIds` 当成该名单。

被合并的角色不再单独计人：兼任者只占一份时间，这本来就是合并要表达的事实——同一个人不会因为身兼两职就在会里坐两遍。

### 结果影响与合理投入

会议产出的影响不同，合理投入也不同。Agent 要把 `outcomeLevel` 判断为：

- `low`（局部）：影响一项工作，容易撤回。
- `medium`（团队）：改变团队承诺、资源或排期。
- `high`（关键）：跨团队、难以逆转，或机会窗口很短。

Agent 在给出具体人员与时长建议时，应当综合这个影响判断。页面把 Agent 推荐配置的实际成本直接作为「合理投入」，不再提供单独的影响级别控件，也不叠加隐藏倍率。影响级别和理由只保留在「判断依据」中，供用户检查 Agent 的判断。安全、法律、人事、紧急和敏感关系工作仍由保护规则优先，不能仅凭成本优化掉。

## 5. 四种处方

- `keep`：产出清楚、同步价值明确、必要角色齐全，值得按当前或近似配置召开。
- `shrink`：会议值得发生，但邀请范围或时长明显过重。
- `async`：主要是信息流动，不需要实时互动；生成可发送的异步替代方案。
- `clarify`：缺少决定性信息；先补充目标或同步理由，再重新称重。

## 6. 当前沙盘状态

HTML 重新计算后使用四种状态，每种对应一种页面底色：

- `balanced`（绿）：还有同步议题，价值底线满足，当前总成本不超过 Agent 推荐配置成本的 115%。
- `overweight`（蓝）：还有同步议题，价值底线满足，但当前成本超过合理投入 115%。
- `async`（橙）：当前配置已经没有任何同步议题，写一条书面更新就够了。
- `underpowered`（红）：缺少必要角色、把必须同步的议题改为异步，或关键议题低于最低有效时长。

判定顺序是 `underpowered` → `async` → `overweight` → `balanced`：底线优先，其次才看重量。

状态是对当前配置的反馈，不会偷偷改变 Agent 的原始结论。`async` 描述的是用户此刻的配置，不等于 Agent 给出了 `async` 处方；一场 `keep` 会议如果被用户把所有议题都移成异步，也会显示橙色。

## 7. 减重不能靠破底线换

`underpowered` 状态下页面不展示「返还时间」，也不生成任何可以发出去的文案。理由是：那点节省来自删掉必要的人或假装必须同步的议题可以异步，把它当成绩效就是在奖励错误动作。这时唯一的建议动作是把底线补回来。

补回底线是确定性动作，只使用已声明的数字：把 `required` 议题改回同步、把同步分钟提到 `minSyncMinutes`、把必要角色补到 `requiredMin`（先从异步知会取回，再从无需参与取回）。不发明新的人数或时长。

合并同样受这条约束：它是承认现实，不是省人的后门。底线检查和补回动作看的都是兼任者本人是否在场——把兼任者移出会议，底线立刻算破，提示会写明这个角色由谁兼任。
